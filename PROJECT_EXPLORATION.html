Project Overview

Dự án giải quyết vấn đề gì

Mục tiêu

Repo xây một backend RAG tiếng Việt cho chatbot tư vấn sản phẩm điện thoại. Khi câu hỏi liên quan product catalog, hệ thống retrieval dữ liệu sản phẩm, rerank passages, rồi dùng LLM sinh câu trả lời.

Final goal

Tạo một API backend có thể nhận chat messages, phân loại intent, truy xuất product knowledge từ vector DB, và trả về message assistant theo format client mong đợi.

Audience

Người học AI Engineering cần hiểu một pipeline RAG thực tế: embeddings, vector search, reranking, prompt construction, LLM adapters, evaluation và benchmark.

Inputs và outputs

LoạiChi tiết
API inputPOST /api/search nhận JSON array chat messages, ví dụ [{"role":"user","content":"..." }].
Data inputCSV product catalog, nổi bật là hoanghamobile.csv với 2,994 dòng gồm _id, title, product_specs, current_price, promotion và color options.
Runtime outputJSON {"content": response, "role": "assistant"}.
ArtifactsLocal Chroma collection trong ./chroma_db, benchmark CSV outputs, evaluation logs trong test folders nếu chạy test/benchmark.

Main features

  • Flask API với CORS cho chatbot client.
  • Semantic router tách route products và chitchat.
  • Reflection layer rewrite chat history thành standalone Vietnamese query.
  • RAG layer hỗ trợ chromadb, MongoDB Atlas Vector Search và Qdrant.
  • Reranker dùng CrossEncoder để sắp xếp lại passages.
  • LLM facade hỗ trợ Gemini, OpenAI, Together, Ollama, vLLM, Hugging Face và ONNX.
  • Evaluation gồm Hit@K, nDCG, BLEU, ROUGE và latency benchmark.

End-to-End Workflow

Request, data và control flow

  1. Client gửi chat history tới POST /api/search.
  2. Reflection dùng LLM rewrite câu hỏi cuối thành standalone Vietnamese query.
  3. SemanticRouter.guide() embed query và so sánh với sample embeddings của route products/chitchat.
  4. Nếu là products, RAG.vector_search() tìm documents từ vector DB đã chọn.
  5. Reranker rerank passages, sau đó serve.py ghép prompt tư vấn bán hàng kèm context.
  6. LLMs.generate_content() gọi backend model tương ứng.
  7. API trả về message assistant.

Setup Guide

Guide suy luận, chưa chạy thật

Các bước dưới đây được suy luận từ README_old.md, pyproject.toml, requirements.txt và code. Trong E1 này không chạy app, không install dependencies, không start server, không chạy runtime tests.

1. Chuẩn bị Python và dependencies

  1. Dùng Python 3.12, khớp .python-version và pyproject.toml.
  2. Theo README, dependency setup dự kiến là uv sync.

2. Tạo env vars theo backend cần dùng

Use caseEnv vars
GeminiGEMINI_API_KEY
OpenAIOPENAI_API_KEY
TogetherTOGETHER_API_KEY, TOGETHER_BASE_URL
OllamaOLLAMA_BASE_URL
vLLMVLLM_BASE_URL
MongoDBCode dùng MONGODB_URI, MONGODB_NAME, MONGODB_COLLECTION; README lại ghi DB_NAME, DB_COLLECTION, nên cần chuẩn hóa trước khi chạy.
QdrantQDRANT_API, QDRANT_URL

3. Chuẩn bị data/vector DB

  • ChromaDB: đặt CSV hợp lệ trong data/; khi collection chưa tồn tại, serve.py sẽ gọi ingestion trước khi serve.
  • MongoDB: cần Atlas Vector Search index tên vector_index.
  • Qdrant: cần collection tương ứng với tên embedding model, thường là phần cuối của model id.

Testing Strategy

Tests và evaluation

Test suite trong repo đo nhiều lớp của RAG system nhưng phần lớn là integration-heavy: cần model thật, API server thật, vector DB thật, network hoặc credentials. Vì vậy chúng hữu ích cho evaluation, nhưng chưa phải unit tests cô lập hoàn toàn.

AreaFilesĐiều đo được
API responsetest/unitTest/test_api_response.pyGửi request tới localhost:5002/api/search.
Chroma retrievaltest_chromadb_vector_search.pyTải CSV bằng gdown, build ChromaDB, assert top IDs.
Mongo/Qdrant retrievaltest_hit@k_mongodb.py, test_hit@k_qdrant.pyHit@1 trên benchmark CSV.
Reflectiontest_reflection.pyKiểm tra các online LLM trả string cho query rewrite.
Reranktest_rerank_ncdg.pyExact match và average nDCG, threshold nDCG > 0.7 và exact accuracy > 0.3.
Answer qualitytest_bleu.py, test_rouge.pyGọi API thật và tính BLEU/ROUGE bằng RAGAS.
Latencybenchmark_inference_time_llms.py, benchmark_inference_time_pipeline.pyThời gian LLM-only và full pipeline theo CSV.

README gợi ý chạy integration tests bằng uv run python -m unittest discover -s ./test/integrationTest -p "test*.py" -v. Lệnh này chưa được chạy trong E1.

Learning Notes

Khái niệm nên học khi onboarding

RAG pipeline

Hiểu query rewriting, semantic routing, embedding, vector search, reranking, prompt augmentation và answer generation.

Vector stores

So sánh local ChromaDB với managed MongoDB Atlas Vector Search và Qdrant, đặc biệt collection naming, index naming và score semantics.

LLM adapters

Facade pattern giúp đổi backend model, nhưng mỗi backend có side effects khác nhau: API keys, server connectivity, model downloads, GPU/CPU memory.

Evaluation

Hit@K/nDCG đo retrieval/rerank; BLEU/ROUGE đo lexical answer similarity; latency benchmark đo cost theo từng stage.

Risks and Open Questions

Điểm chưa rõ và rủi ro kỹ thuật

  • pyproject.toml khai báo readme = "README.md", nhưng repo hiện chỉ có README_old.md.
  • Understand-Anything layer trỏ tới document:AGENT.md, nhưng worktree hiện báo AGENT.md đã bị delete và có AGENTS.md untracked.
  • README env vars cho MongoDB dùng DB_NAME/DB_COLLECTION, code dùng MONGODB_NAME/MONGODB_COLLECTION.
  • Trong rag/core.py, một số check dùng if self._collection_exists: thay vì gọi self._collection_exists().
  • Trong insert_data/build_chromadb.py, check combined_infomation bị typo nhưng drop combined_information.
  • Tests có nhiều dependency runtime: localhost server, external APIs, Google Drive download, vector DB credentials, model downloads.
  • serve.py chạy Flask với debug=True, phù hợp dev hơn production.
  • index.html được index là markup nhưng nội dung hiện giống product specs text, cần xác minh vai trò thật.
